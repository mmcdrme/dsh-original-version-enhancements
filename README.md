# 原版功能增强 / Original Version Enhancements

「原版功能增强」是一个 DSH Web 客户端插件。它在设置里提供一个自己的页面
（设置 → 原版功能增强），用开关控制各项增强，并把官方界面缺少的聊天记录管理、
自动化任务增强集中到同一处。

> Original Version Enhancements is a DSH Web client plugin. It adds its own
> settings page (Settings → Original Version Enhancements) with per-feature
> switches, an archived-session manager, and an automation enhancement panel.

## 功能 / Features

### 1. 工作步骤展示快捷切换

把「设置 → 通用设置 → 工作步骤展示」的四个档位（简洁 / 标准 / 详细 / 完全展开）
复制成四个 24px 图标按钮，放在「用资源管理器打开」工作区按钮的左侧：

- 会话标题栏：`conversation.session.header.utilities`，`order: -20`
- 右侧文件面板：`sidebar.right.tab.files.actions`，`order: -10`

按钮共享 `ui-chat.transcriptView`，与设置页双向同步。插件页上的「工作步骤展示快捷切换」
开关关闭后，两处按钮立即隐藏，Host 配置保持不变。

### 2. 聊天记录管理

聊天记录管理现在有两个入口：

- **独立设置页**：设置 → 已归档会话。按名称、工作区或聊天内容搜索已归档会话
  （聊天内容搜索最多返回 20 条）；一键「取消归档」，使用官方
  `workspaces.unarchiveSession`；「永久删除」带二次确认。
- **会话右键菜单**：任意会话行的右键菜单新增红色「永久删除」，点击后弹出同一套确认框。

#### 移动 / 复制会话到其他工作区

会话右键菜单在「永久删除」上方新增两行，图标与文字分别使用蓝色与绿色：

- **移动到工作区**（蓝色 · 文件夹+箭头图标）：把会话搬到另一个工作区，**会话标识保持不变**，原工作区不再显示它。
- **复制到工作区**（绿色 · 双卡片图标）：在另一个工作区留下完整副本，原会话保持不变。

点击后弹出「选择目标工作区」面板：只列出当前工作区之外、目录仍然存在的工作区（显示名称与路径）。
鼠标滑过任一行时整行按当前操作着色：移动为蓝色淡底 + 蓝色描边，复制为绿色淡底 + 绿色描边。

- **移动**：面板单行选择，点击目标工作区立即执行。
- **复制**：每行带复选框，可多选；底部按钮随选择变为「复制到 N 个工作区」，一次复制到全部所选工作区，
  选中的行显示绿色勾选与绿色淡底；部分工作区失败时只报告失败的那几个。

「移动 / 复制」只对未归档的会话显示：已归档的会话在侧边栏是单独的「已归档」视图，右键菜单与官方一致
只保留「取消归档」和本插件的「永久删除」，不会出现把它们直接塞进别的工作区的入口。
归档状态还没同步到浏览器时（例如页面刚打开、工作区状态仍在加载）这两行会先隐藏，避免「先出现再消失」的闪烁；
选择器里的目标工作区列表也跟随工作区状态实时刷新，不会出现打开时列表为空、过一会儿才有的情况。

#### 独立窗口

会话右键菜单里的「在独立窗口打开」把该会话放进一个**独立的程序窗口**，主界面不再进入它；
菜单里它排在「移动到工作区」**上面**（把会话移出页面比移到别的工作区更轻）。

- **两种移出方式**：右键菜单，或直接把侧边栏的会话行**拖到主窗口外面**放手。拖动时一旦指针离开
  浏览器窗口、松手又没有落在任何可接收目标上，就按"移出到独立窗口"处理；在窗口内正常拖动排序/
  拖到别处不受影响，按 Esc 取消拖动也不会误触。
- **窗口是一个额外的 exe**：`native/OveWindow.exe` 是插件自带的小程序（WinForms + WebView2），
  由 Host 半启动。它有**自己的任务栏项**、自己的最小化/还原/最大化，**主窗口最小化或切到后台都不影响它**。
  窗口里是**该会话本身**：左侧侧边栏不显示，整窗就是对话（标题栏显示会话名）。exe 带自己的图标
  （蓝底列表图标，任务栏和窗口左上角都是它），并声明了 Per-Monitor V2 DPI 感知，所以在 150% 缩放的屏幕上
  文字也是清晰的，不会被系统位图缩放糊掉。
- **为什么需要这个 exe**：桌面客户端不给插件创建原生窗口的能力（`window.open` 只放行 http/https 且转给
  系统浏览器，也没有 Document Picture-in-Picture），应用内 iframe 又会随主窗口一起最小化。这个 exe 由
  Host 用带启动令牌的地址打开、再由 WebView2 装载会话页，所以是真正的独立窗口。
- **可以同时开多个**：每个窗口有自己独立的 WebView2 配置目录和会话，因此互不干扰——同时移出几个会话
  就是几个独立窗口，各自最小化/还原/关闭，互不影响；关掉其中一个只回收它自己的标记与临时目录。
- **打不开就退回应用内窗口**：没有 WebView2 运行时、没有 Windows、或者 `connection` 服务缺失时，
  自动改用应用内浮动窗口（同一套外观设置），并在标题栏说明；不会留下一个空白窗口。
- **外观可调**：「设置 → 原版功能增强 → 独立窗口外观」调整窗口不透明度（30%–100%，原生分层窗口，
  内容一起变透明）、默认大小（紧凑/标准/宽大）和**静音**（默认开启，独立窗口不播放提示音/音效，
  避免后台会话突然响一声），三者对新窗口生效；窗口本身还可以拖边框缩放。
- **只占对话本身**：窗口里没有左侧侧边栏，空的侧边栏轨道也被压掉，阅读列居中；窗口宽度按上面的
  「默认大小」来，所以不会留出大片左侧空白。右侧边栏（工作区文件 / 代码审查 / 终端 / 浏览器等）
  照常可以打开，打开时对话列自动让位。
- **打开窗口不会补响提示音**：小鲸鱼挂件的「上一轮结束」提示音靠本地记住的轮次序号判断，全新的
  WebView2 配置目录没有记忆，第一次轮询就会把历史轮次补播一次；窗口启动时音频上下文尚未解锁，
  这一声会一直压到用户**第一次点击**才响，听感就是"点哪儿都响一下"。独立窗口会先把首次轮次对齐成
  静默基线，此后真正新结束的轮次才照常出声；静音开关仍然有效。
- **加载动画**：窗口先显示"正在载入会话…"和一条滚动的进度条（令牌换取登录态的那一小段），随后是
  会话页自己的转圈动画；**对话真正渲染完成之前不会露出半成品页面**（骨架、空侧栏都不会闪现），
  加载完成后淡出。
- **移出后主界面仍显示会话名**：会话行照常留在原工作区，只是整行套一圈**淡蓝色、向内缩进 4px** 的边框
  （`#7dd3fc`，2px），不与会话选择器悬停时的 2px 蓝色描边重叠。
- **未移回前不能在主界面进入**：单击这一行不会打开会话，只在底部提示
  「该会话正在独立窗口中显示；双击这一行可强制移回并打开会话」。**双击**这一行就是快捷的「移回并打开」：
  立刻关闭对应窗口、去掉边框，并把该会话切到主界面显示，同时提示「已移回主界面并打开会话」。
- **移回主界面**：菜单项在移出后变为「移回主界面」，点击即关闭那个程序窗口、去掉淡蓝边框。
  直接点窗口右上角关闭也一样：Host 立刻知道进程退出，主界面随即解除标记（不需要等心跳超时）。
- **窗口状态由 Host 记账**：哪个会话开着窗口、是否已经渲染出内容，都存在 Host 进程里，主界面每 1.5 秒
  取一次；因此跨进程也准确，窗口崩了/被关掉都能立刻反映到侧边栏。
- **WebView2 数据目录**：默认放 `%LOCALAPPDATA%\dsh-ove-window\webview2`；如果该目录不可写
  （某些沙箱只放行工作区），退回插件目录下的 `.webview-data/`（已在 `.gitignore` 里）。
- **插件页开关**：「设置 → 原版功能增强 → 独立窗口」可整体关闭：菜单项、拖出、描边和窗口一起移除，
  并自动移回（清标记、关闭已打开的窗口）。

删除当前选中的会话时，主面板会像官方「归档会话」一样立刻离开这个会话（清空选中、释放引用、回到新建会话页），
而不是停在一个已经删除的对话上。

**永久删除带 10 秒可撤销。** 确认后会话立刻从列表消失（工作区账目与投影缓存照旧清理），但它的存储
目录不是被直接抹掉，而是移进 profile 目录下的回收区（`deleted-sessions/<token>`）。随后弹出深色通知：
「永久删除 · 会话名」、「N 秒内可撤销」、「撤销」。10 秒内点「撤销」会把目录原样放回、刷新工作区
表头索引、重新登记到原工作区（原本已归档的仍回到归档集合、原本置顶的仍置顶），并重新预热投影缓存——
恢复出来的会话立刻就有标题，不会是「未命名」。倒计时结束或点通知右侧的「×」才真正删除；进程在窗口内
退出也不会永久留下数据：Host 下次启动会清掉超过 1 小时的回收项。连续删除多条时会各弹一条通知并各自
倒计时、各自可撤销，不会互相顶掉。删除、撤销、丢弃三个路由都要求同源 + 同一个确认头，链接或表单无法
触发，请求体也限制在 8 KB。

**回收区不会留下无人能撤销的孤儿。** 回收索引是所有撤销的唯一凭据，因此它写失败时不会假装成功：
写索引失败会把目录搬回原处并让这次删除返回「未确认删除成功」；万一搬回也失败，删除结果会带上目录
现在的真实位置。启动清扫除了丢弃超时条目，也会清掉索引里没有的目录（它们只能来自失败的搬入）。
撤销本身占用与删除/移动相同的会话预留，因此"撤销"和"删除"同一会话不会互相踩到；原位置已有同名目录
时以 rename 的结果为准报冲突，不动任何文件。

执行完成后面板关闭，并弹出与官方「已归档会话」同款的**浮动深色通知**（窗口顶部居中，6 秒自动消失，
右侧可关闭），通知上带「撤销」：

- 撤销复制：删除本次新建的全部副本。
- 撤销移动：把会话复制回原工作区，再删除目标工作区里的那一份（反向移动）。凭据同时带上源工作区 id
  与源目录：会话原本不属于任何工作区（侧边栏的「未分组」）时，靠 Host 返回的 `cwd` 按目录解析回源。
- 撤销成功后再弹一条「已撤销」；失败时提示具体原因，包括「源目录不在任何工作区，无法撤销」。
  根本没有任何源位置可解析时，通知上不会出现「撤销」按钮，不会给一个必定失败的入口。

DSH 中「会话属于哪个工作区」由会话记录里不可变的 `cwd` 决定，工作区注册表也用它校验归属，
因此不存在原地改归属的接口。**复制**读取源会话完整的事件日志，在目标工作区目录下写出一条 id
全新的完整会话；**移动**则先把源会话目录按「改名隔离」流程挪出会话根目录（与永久删除同一套身份校验），
再在目标工作区目录下用**同一个会话 id** 重建日志，随后刷新工作区注册表的表头索引并登记到目标工作区。
因此移动后会话标识不变：链接、正在打开的对话、外部绑定都不会失效，也不会变成「另一个会话」。
会话仍有未结束回合时会被拒绝（提示等回合结束后再试），以免复制出半截对话。
新会话直接写入持久化并预热投影缓存——不走 Agent 生命周期，是因为生命周期句柄会随插件重载被销毁，
已摘载的会话在宿主重新索引前会从会话列表里消失。移动失败时按相反顺序回滚：先删掉重建的日志，
再把隔离的原目录原样还原，绝不同时留下两条同 id 的日志。

**失败也要回滚到底。** `create` 已经落盘表头之后的任何一步（append / flush / 落盘校验）失败，
不再只把错误向上抛：写入路径会按 id 清掉这次创建，然后才报告失败。移动失败时先确认新日志已经
不存在，再还原隔离目录；清理不掉时返回 `move-partial` 并带上隔离目录路径，而不是静默成功或
留下两份同 id 日志。这套回滚与删除共用同一套隔离/身份校验，并明确跳过工作区账目清理，
以免把随后要还原的源会话从工作区里摘掉；若后端尚未索引新表头、`list/stat` 还看不到它，
回滚还会直接扫描持久化根，按 id 找到刚写入的日志目录并隔离删除。

**移动与删除互斥。** 移动在入口就占用该会话的删除预留（`agentHandles.reserve`），整个改名—重建—
登记过程都持着它，结束时释放；复制则在落盘后、登记前占用新副本 id。两个窗口同时对同一会话
点「永久删除」和「移动到工作区」时，后到的那个得到「正在删除或移动中」，不会互相把目录改没。

**落盘校验。** 副本写完必须通过校验才会被登记进目标工作区：持久化里能查到这条会话、事件条数不少于
源日志、日志文件存在且非空。任何一步不满足就回滚删除副本并报错，而不是留下一条「点开历史加载失败」
的幽灵条目。另外，从带 `session/end-seed` 的日志（分叉出来的会话）复制时，副本表头会沿用
`isSeeded` 并把继承前缀长度一起写进持久化——缺少它的副本后端不会落盘，这也是之前
「复制/移动后会话损坏」的根因。

**复制/移动出来的会话不再「未命名」。** 投影缓存只接受与表头身份完全一致的记录，而一条普通
（非分叉）日志自身也带着收尾用的 `session/end-seed` 标记。此前把它当成"继承前缀"传给
`coldSnapshot`，缓存服务会以「unseeded … inherited event count must be 0」拒收整条记录（错误被
吞掉），于是副本没有标题，侧边栏显示「未命名」，直到点开该会话才由冷读补写缓存。现在只有
`isSeeded` 为真的日志才计算继承前缀，非分叉日志一律按 0 传递；写入后还会等缓存真的能读出标题
再返回，保证紧随其后的会话列表刷新看到的就是原会话的标题。

永久删除默认只接受已归档且未被宿主加载的本机会话，并通过持久化写入句柄独占校验。
插件会跟踪 Host 的 Agent 生命周期句柄，先把会话停用再删除。句柄表保存在 Host 进程级，
插件被重载（升级插件、改配置）之后依然有效——旧实现把句柄表放在插件模块里，重载后就忘了
自己加载过的会话，于是这些会话只能走「强制删除」。

删除确认框在任何页面都自带样式并挂到 `document.body`，不再依赖插件其它面板已经渲染过
（以前从会话右键菜单删除时可能完全没有样式，看起来像界面坏掉）。

只有当会话在本插件第一次加载之前就已打开（Host 里没有对应句柄）时，确认框才会给出
「重试 / 强制删除」：重试用于刚重启过 DeepSeek Harness 的情况；强制删除跳过写入句柄
直接移除磁盘上的会话目录。该操作会让宿主中的该会话立即失效，建议删除后重启
DeepSeek Harness。工作区的归属记录会当场清理，侧边栏不再保留这一行。

需要迁移的旧版存储格式不再被拒绝删除：为了删除而打开旧日志会发布一次迁移，所以这类日志
（以及打不开的损坏日志）改为不经写入句柄定位，定位结果仍要过一遍目录身份校验再隔离删除。

**存储只剩空壳的会话也能删。** 写入被打断时会留下一个没有日志文件的会话目录，或者只剩表头、
日志已丢失；这类会话在侧边栏里看得见、点开却加载失败，普通删除又会因为「找不到会话」而拒绝。
现在会在这两种情况下定位那个空壳目录，用同一套「先改名隔离、再校验身份、最后删除」的流程清掉，
不会再出现删不掉的僵尸会话。同一 id 的空壳可能不止一个（每个 project 目录一份），删除会收集
**全部**命中并逐个清掉，然后在删除后再扫一遍；空壳在改名前后都用 `dev/ino/mode/size/birthtime`
比对，校验的是「还是原来那个目录」，而不仅是「它还是个目录」。

删除成功后会同时清掉该会话的归档/置顶标记、它在工作区注册表里的归属，以及投影缓存里的记录。
只删日志是不够的：工作区仍会把它列在侧边栏，形成一条「点开就加载失败」的**幽灵对话**（以前要重启宿主
或手工改 `workspace.json` 才会消失）。插件启动时还会按会话存储逐条核对：注册表里已经没有对应日志的
会话归属、以及没有日志对应的投影缓存记录都会被清理，所以旧版本删除会话留下的幽灵条目也会一并消失。

聊天记录管理改编自 [dsh-chat-manager](https://github.com/WSL043/dsh-chat-manager)
v1.5.21（MIT License，Copyright (c) 2026 WSL043）。
与原版的差异：无法取得句柄时提供显式「强制删除」；取消归档走官方 Client 服务而不是额外路由。

### 3. 自动化任务增强

自动化任务增强把原 `automation-console` 插件的能力并入本插件，并按 DSH 0.2.x
的新版 Schedule 服务与「自动化任务」页的界面重写：

- **与官方页同构的独立面板**：侧栏「自动化增强」（`main` 面板 key 与 `sidebar.panellist`
  id 均为 `original-version-enhancements.automation`，`order: 11`）。标题、`+ 新建`
  按钮、`已开启 / 已暂停 / 已结束 / 全部` 分栏、搜索框、全选、时钟图标的行样式与空态插画
  都对齐官方页；点击任务在右侧打开同款「规则」编辑抽屉（名称 / 内容 / 执行位置 /
  关联工作区 / 重复 / 时间 / 自定义 RRULE / 自定义 Cron）。抽屉占满整块面板高度（底部不再留空白），
  `保存` 固定在抽屉底部的独立页脚，不随表单滚动——表单再长也不必先滚到底才能保存；
  常规窗口高度下新建任务的整张表单无需滚动即可看全。官方页及其数据不变，两处操作同一份任务。
- **分栏计数**：四个分栏后分别以绿、黄、红、黑显示任务数量，数字实时跟随任务表。
- **全选在列表上方**：`全选` 复选框独占一行、位于任务列表之上，与行首勾选框完全对齐，
  只作用于当前分栏与搜索词命中的任务。
- **免对话创建 / 在会话中创建**：`新建` 是官方页同款的双段按钮——左侧直接打开编辑抽屉
  （免对话创建），右侧下拉提供「在会话中创建」（新开一段会话并填入创建指令）与「手动创建」。
  「重复」下拉与官方页一致——每周 / 周一至周五 / 每天 / 每 N 小时 / 每 N 分钟 / 每月 /
  仅一次（指定时间）/ 自定义规则 / 自定义 Cron（直接填 5 字段 Cron 表达式），并额外提供
  **仅一次（延时）**：延时可按分钟或**秒**填写，到点只运行一次。时间字段精确到秒（`时:分:秒`）。
  新建默认「仅一次（延时）：30 分钟」；原来的「重复」勾选框已取消，一次性与循环直接由下拉选择。
- **运行历史记录**：编辑已有任务时，抽屉顶部有「编辑任务」和「运行历史记录」（带条数）两个页签，
  运行记录按时间倒序列在第二个页签里（时间 + 目标会话 + **该次投递的任务内容**），
  **只读展示**，不提供删除或隐藏。
- **自定义规则示例**：选择「自定义规则」时，RRULE 输入框下方给出三条可直接点选填入的示例
  （每周一三五、每两天、每月 1 号），避免手写 RRULE。
- **立即投递**：行内与编辑抽屉都提供「立即投递」。第一次点击永远先用宿主自带的「立即执行」（`service.run`）：
  送达任务真正指向的会话，并在原任务上留下运行记录；「新建并复用」任务由它创建预留的会话、把**原任务的
  执行位置改写为这次新建出来的对话**（之后都复用该对话），成功与否都不改规则的 `scheduledAt`。
  - **投递间隔**：宿主规定同一任务两次投递之间有最小间隔（`会话`目标 60 秒；`每次新建`按配置），
    间隔内原版会拒绝本次投递。此时行内与抽屉里的按钮变成黄色「立即投递(间隔)」——点击后弹出「投递提醒」，
    说明继续投递会绕过间隔、**这次投递可能无法记录运行记录**；选择「继续投递」后改用增强版的克隆：
    创建一个与原任务完全相同（名称、内容、执行位置一致）、只把时间设为「2 秒后」的临时任务，由宿主调度器
    真正触发一次投递；该临时任务在本插件面板中隐藏，投递结束（无论成功与否）后立即删除自身，原任务的
    重复规则、启停状态与运行记录不受影响。
  - **正在投递不等于间隔内**：宿主把「正在执行 / 仍在间隔内 / 上次投递尚未结束」都折叠成同一个
    `schedule_execution_pending`。任务真的在投递时，再投一次会让同一会话收到两条相同提醒，因此行内与
    抽屉按钮显示「正在投递…」并禁用；万一撞上竞态，宿主侧返回 `schedule-execution-active`，
    面板只提示等待，不会弹出「投递提醒」、也不会创建克隆。
  - **对账**：若进程在投递间隙退出，宿主任务变更或插件启动时的对账会清理遗留的临时任务。宿主没有
    「隐藏任务」标记，因此官方「自动化任务」页在这不到两秒的存活期内仍可能闪过这一行；本插件面板不会
    显示它，它也不会进入任何搜索结果或计数。
- **编辑已结束任务不会把它重新武装**：`active` 只在「暂停 ↔ 已开启」之间表态，`ended` 是终态，
  保存时既不发送 `active`，也不会把原样不变的重复规则当成「规则改动」提交（宿主把后者当成 re-arm：
  一次性任务会抛 `not_future`，循环任务会被悄悄改回已开启）。
- **保存前比对规则**：编辑器总是从当前行重建整条规则，Host 侧先与已存规则比对，相同就不提交，
  因此打开后只改标题也会保持原有规则不变。
- **并发保存提示**：保存时带上渲染所用的 `expectedUpdatedAt`；若这期间任务已被别处修改（或定时投递
  更新了运行状态），会弹出「任务已被其他位置修改」并给出「取消 / 覆盖保存」，不会静默覆盖。
  抽屉未被编辑时，列表轮询带来的新修订号会被自动接上，避免投递一次就导致保存报冲突。
- **行内悬浮操作**：浮到任务行上按状态出现绿色「立即投递」、黄色「暂停任务 / 恢复任务」与红色
  「删除任务」（悬停时仍保持红字）；删除任务带二次确认，消息与会话保留。
  动作浮在行的右上角，不占正文宽度；只有真正的鼠标悬停会显示，勾选复选框后不会残留。
- **任务名后的执行位置**：任务名后附带 `任务名 (工作区/会话名)`——工作区为黑色粗体，
  括号、`/` 与会话名不加粗（会话名为蓝色）；缺少其中一项时只显示存在的那一项。
- **关联工作区会点亮侧边栏**：「关联工作区」与「关联会话」用同一个下拉组件（`combobox` + 浮层
  `listbox`，同样的按钮、圆角、阴影与高亮行样式，不再是原生 `<select>`）。展开列表后，鼠标移到哪个
  选项（或用 `↑/↓` 移动），侧边栏对应的**工作区分组行**就用**黄色**描边标出：会话行蓝色、溢出
  「展开其余」行绿色、工作区分组行黄色，三者一一对应；移出列表或关闭列表即恢复原样。
  「不指定（跟随默认）」指向自动创建的默认工作区行（列表里也显示为「默认工作区」，与侧边栏一致）；
  选中的目录已不属于任何工作区时，指向「未分组」分组行，不会静默什么都不点亮。抽屉关闭时也会清掉标记。
- **新建/编辑抽屉里的下拉全是同一个组件**：执行位置、关联工作区、关联会话、重复、延时单位都使用
  同一套 `combobox` + 浮层 `listbox`（按钮、圆角、阴影、悬停高亮行完全一致），抽屉里不再有原生
  `<select>`；`↑/↓` 打开并移动、`Home/End`、`Enter` 选取、`Esc` 关闭、`Tab` 收起，
  `aria-activedescendant` 始终指向当前行。
- **键盘与读屏**：关联会话下拉是 `combobox` + `listbox` 结构，`aria-controls` 指向列表、
  `aria-activedescendant` 跟随当前高亮项，读屏能报出「当前是哪一条会话」；「新建方式」菜单
  打开后焦点落在第一项，`↑/↓` 循环、`Home/End` 跳转、`Esc` 关闭并把焦点还给触发按钮，
  `Tab` 离开时自动收起。
- **错误文案**：宿主返回非 JSON、连接失败或没写原因时，不再把 `Failed to fetch`/`HTTP 500`
  拼进中文提示，而是显示「无法连接宿主…」「宿主返回了无法解析的响应（HTTP 500）…」等可行动文案，
  原始错误只进 `console.warn`。
- **工作详情档位不会卡住**：提交后若宿主接受但表单值没有变成该档位，2 秒后自动解除 `aria-busy`
  并标记失败，不会让高亮永久停在错误档位。
- **重复规则统一显示**：原版「自动化任务」页把每个预设（每 N 分钟 / 每 N 小时 / 每天 / 每周 / 每月 /
  仅一次）都存成一条 `rrule` 记录，本面板用同一套分类把它读回人类可读的摘要——例如
  「每 100 分钟」「每 3 小时」「每 2 天 09:30」「每周 周一、周三、周五 09:00」「每月 5 日 09:00」「仅一次」；
  只有预设表达不了的自定义规则才显示「自定义」。原版页创建的任务因此不再一律显示成「自定义」。
  编辑抽屉仍保留原始 RRULE 文本，打开或保存不会改写规则本身。
- **编辑往返不改写规则**：`每周` 支持**多选星期**（一组开关，可同时选周一和周四，保存、再打开都保持
  所选的全部星期，不再被压成一天）；**最后一个星期不能被取消**——只剩一天时再点它不会生效
  （按钮带 `data-locked`，提示「至少要保留一个星期」），因此不会出现「一天都没选」再被悄悄存回
  周一的情况；周一只是 `timingOfDraft` 里出错时的防御性兜底，界面上不再走这条路径。`工作日` / `每月` / `自定义` 在编辑时从规则自身的 `DTSTART`
  反解日期与时刻，打开后原样保存不会把任务挪到「现在 + 30 分钟」；`仅一次（延时）` 在秒数不是整分钟时
  （例如 90 秒）保留秒单位，不会四舍五入成 2 分钟。`BYDAY` 按**集合**判断「工作日」，
  `MO,TU,WE,TH,FR,SA` 不会被当成周一到周五而改写。
- **引导表单只认它能完整表达的规则**：`工作日` / `每月` 只接管「`FREQ` + `BYDAY`」或「`FREQ` +
  `BYMONTHDAY`」这种规则；带 `INTERVAL=2`、`UNTIL`、`COUNT` 或额外行的规则落到 `自定义` 原始
  RRULE 编辑器，原样保存，不会因为改个标题就把「隔周」变成「每周」或丢掉结束日期。
- **后台轮询不会吞掉别人的编辑**：抽屉只在「列表里的任务仍与当前表单完全一致」时采纳新修订号
  （例如一次投递只改了运行状态）；标题、内容或规则被别处改过时不再静默采纳，保存会如实报冲突。
  运行状态（暂停/恢复）同样参与比较：别处暂停的任务不会被本抽屉的下一次保存重新恢复，
  采纳修订号时也会一并同步运行状态。抽屉本身不提供「启用」开关（暂停/恢复是行上的独立动作），
  因此保存请求从不携带 `active`——即使点了冲突框里的「覆盖保存」，也只覆盖内容，不改运行状态。
- **彩色操作回执**：保存/恢复/绑定等成功提示为绿色，暂停为黄色，删除为红色，立即投递为中性色，
  因间隔而走克隆的那次为「已投递（可能未记录运行记录）」，4 秒后自动消失。
- **每秒倒计时**：行内「下次计划时间」后的相对时间每秒刷新，不足一分钟显示为「xx 秒后」；
  已暂停的任务同样显示倒计时。
- **浮动的操作条**：勾选栏、操作回执与错误提示不占用列表上方的高度，而是浮在「全选」一行上。
  勾选栏是一组浮动的控件（没有白色底框），「已选 N 项」紧贴在「绑定到多个会话」左侧、整体靠右；
  操作回执（添加/绑定/暂停/恢复/删除等）与错误提示仍保留各自的彩色底提示条，
  左边界从「全选」右侧再向右 100px 处开始，右边界到整行末尾。
  因此「全选」与任务列表左边界与搜索框完全对齐，勾选或执行操作时列表完全是静止的。
- **切换分栏即清空选择**：在「已开启 / 已暂停 / 已结束 / 全部」之间切换会取消当前勾选，
  避免选中了别处已不可见的任务；批量绑定成功后同样自动取消选择。
- **任务下方的说明行**：说明行可使用整行宽度（悬浮按钮浮在右上角，不挤压文字），
  右边界与「删除任务」的右边界对齐，换行更晚。
- **抽屉底部动作**：「立即投递」为绿色、「暂停任务 / 恢复任务」为黄色、「删除任务」为红色，
  三者同为描边 + 浅色底的按钮样式。
- **批量暂停 / 恢复**：批量操作栏里，在「已暂停」分栏显示绿色「恢复所选」（把所选任务重新开启），
  其余分栏显示黄色「暂停所选」；「绑定到多个会话」为蓝色描边样式；成功后自动取消选择。
- **批量删除**：勾选多个任务后一次删除，按钮与「暂停所选」同款描边样式但为红色，带二次确认；
  已投递的消息与目标会话保留。
- **多会话绑定**：勾选一个或多个任务后一次绑定到多个会话（同标题、同指令、同重复规则），
  每个任务 × 每个会话各一份；已归档会话被过滤，已经绑定过的会话自动跳过，
  一次性任务若时间已过则拒绝复制并提示原因。判断「已绑定」只依据本插件创建的副本任务 id
  （记录在 profile 的状态文件里），不再按「标题 + 指令」猜测——两个同名同内容的任务不会互相
  把对方的会话算成已绑定。
- **关联会话列表**：下拉里的每个会话显示为「工作区/会话名」，**工作区加粗**，与任务名后的
  执行位置写法一致；同名会话不再合并，靠工作区分开，逐条列出（已归档、以工作区名占位的空会话
  仍然过滤）。下拉是自绘的，不再依赖浏览器原生 `<select>`，因此条目可以分两段着色。
- **同名会话的区分**：同一工作区里重名的会话，在会话名后追加蓝色的 `#XXXXXXXX`（会话 id 的前 8 位）
  以互相区分，下拉、触发器与批量绑定对话框一致；不重名时不显示，不给普通条目添噪音。
  另外，下拉里**当前高亮的那一条**（鼠标停在哪、方向键移到哪）也一定带上这串短 id，
  所以即使两个会话重名或名字很像，高亮条本身也说明了它究竟是哪一个会话。
- **指向侧边栏**：在下拉里用鼠标或方向键移动选择时，会同步指向左侧工作区列表：会话可见时
  给那一行加蓝色外框；所在工作区折叠时先自动展开该工作区、再框住会话行；会话被收在
  「展开其余 N 个会话」后面时，改框住那一行展开按钮——因为那是一个「控件」而不是会话本身，
  它用**绿色**外框加绿色淡底，一眼就能和会话行区分开（同样不自动展开，点它即可看到会话）。
  工作区不在当前视图（滑轨模式、搜索过滤）时不做任何改动。
- **取消选择会还原侧边栏**：为了指向会话而临时展开的工作区，属于「借用」而不是用户的选择；
  下拉在没有选中任何会话的情况下收起（`Esc`、点别处、滚动、切走窗口），这些工作区会按
  用户最后一次亲手操作的状态（展开/折叠）复原；真正选中一条会话时则保持展开，让刚选中的会话
  留在视野里。用户在下拉打开期间亲手折叠过的工作区不会被重新展开，也不会被还原操作打扰。
- **展开期间亲手折叠工作区不会被"弹回去"**：下拉打开、借用展开生效时，用户直接点工作区行
  （整行就是展开/折叠开关）会**一次点击就折叠**——这次点击先按它落到的位置决定该工作区的状态，
  其余借用的工作区在点击处理完之后才归还，所以行不会在按下与抬起之间被挪走，也不会被
  还原动作再展开一次。点侧边栏里的会话行或「展开其余 N 个会话」行同样按原样生效（不在这时
  折叠它们所在的工作区），用户一旦直接操作侧边栏，这些展开就归用户所有，随后的关闭不再收回。
- **投递后清理（仅一次性任务）**：逐任务开关，只在「仅一次（延时）/ 仅一次（指定时间）」的任务上出现
  （循环任务不显示该开关，避免误删）。一次性任务投递完成（状态 `ended` 且有投递回执）后由 Host 侧删除；
  宿主 `schedule/changed` 事件与插件启动时都会执行对账。编辑抽屉里的勾选会随保存一起写入。

投递后清理的标记与「立即投递」临时任务的隐藏标记都保存在 profile 目录的
`original-version-enhancements.automation.json`。这份侧车是持久索引（自动清理开关、批量绑定生成的
副本 id、隐藏克隆的来源），所以写入是原子的（临时文件 + rename），并在每次写入前把上一代留成
`.bak`；读到损坏/截断的文件（包括能解析但不是对象的 `null`/`[]`）时先回退 `.bak` 并记录告警，
不会静默把三份索引一起清零。只有**当前主文件本身可用**时才会覆盖 `.bak`，因此一次失败的保存
不会毁掉唯一的好备份。源任务被删除后，它在侧车里留下的副本索引会在对账时一并丢弃，不会无限增长。
面板的「运行记录」条数按任务的修订号缓存，同时最多 60 秒复用一次，历史被裁剪后不会长期显示旧数字。
### 4. 发送历史重溯

输入框里按快捷键可以找回刚刚发送过的内容，像 shell 的历史记录一样上下走：

- **向上重溯**（默认 `Alt+P`）：把上一次提交的内容放回输入框；再按一次继续向前，最多走到
  配置的条数（默认 100 条，可设 1–100）。走到最早一条后继续按不会绕回，停在最早一条。
- **向下回退**（默认 `Alt+B`）：回到较新的一条；在最新一条上再按一次，输入框变回空内容，
  即「退到底部就是空内容」。
- 两个键都只在输入框获得焦点时生效（组合键里至少带一个修饰键），在设置页的搜索框或别的插件
  输入框里按同一个组合键不会干扰。
- 发送内容是**只有成功提交**才会记录：输入框进入发送状态、随后草稿被清空时记为一条；发送失败
  （草稿原样保留）不会记录。手动清空草稿也不会被当成发送。
- 重溯出来的内容可以直接再发送；一旦手动修改，下一次按键会重新从最新一条开始，不会接着旧位置走。
- **回溯范围可切换**：「独立会话回溯」关闭（默认）时所有会话共享最近一份历史；开启后每个会话
  只重溯自己发送过的内容。切换这一项会先弹窗说明「更改此项将自动清空历史记录」，确认后清空
  全局与按会话两份历史再切换，取消则保持原样。
- 历史只存在当前浏览器的 `localStorage`（全局：`original-version-enhancements.history.v1`；
  独立会话：`original-version-enhancements.history.sessions.v1`），不写进会话记录、不上传；
  清空浏览器数据即清空历史。
- 按键、条数与会话范围在「设置 → 原版功能增强 → 发送历史重溯」里修改；关掉「发送历史重溯」
  开关时整块设置区一并隐藏。键位按钮点一下进入录制，按下组合键即保存（Esc 取消），
  **点击按钮以外的任何位置也会自动放弃本次录制**；两个方向不允许用同一个组合，条数设置立即裁剪历史。

## 开关与持久化

- 五个开关（工作步骤展示快捷切换、聊天记录管理、自动化任务增强、发送历史重溯、独立窗口）位于插件页顶部，
  实时生效，无需刷新。
- 关闭「聊天记录管理」会立即移除「已归档会话」设置页与会话右键菜单项；重新开启即可恢复。
- 关闭「自动化任务增强」会立即移除侧栏面板与对应面板页；官方「自动化任务」页不受影响。
- 关闭「发送历史重溯」会立即卸载输入框里的桥接组件：既不记录新发送，也不再响应这两个组合键，
  已有的历史仍然保留，重新开启即可继续使用；插件页上的整块重溯设置也随开关隐藏。
- 关闭「独立窗口」会立即移除菜单项、拖出与描边，并把仍标记为独立的会话全部移回（清标记、关闭本页打开过的窗口）。
- 开关保存在当前浏览器的 `localStorage`（`original-version-enhancements.flags.v1`），
  键位、条数与回溯范围在 `original-version-enhancements.recall.v1`，清除浏览器数据会恢复默认
  （五项均开启、`Alt+P` / `Alt+B`、100 条、所有会话共享一份历史）。

## Host 路由

只在 Host 提供对应服务时注册，缺失时静默降级，不影响插件其余部分：

- `POST /plugins/original-version-enhancements/archives/search` — 归档内容搜索
- `POST /plugins/original-version-enhancements/sessions/delete` — 永久删除
  （需要 `x-dsh-session-delete-confirmation: delete-session` 确认头与同源校验；正文带 `retain: true`
  时把目录留在回收区，返回 `value.retained.token`）
- `POST /plugins/original-version-enhancements/sessions/restore` — 撤销一次保留的删除（正文 `{token}`，
  同一个确认头）
- `POST /plugins/original-version-enhancements/sessions/purge` — 丢弃一条保留的删除（正文 `{token}`，
  同一个确认头）
- `POST /plugins/original-version-enhancements/sessions/transfer` — 移动 / 复制会话到其他工作区
  （需要 `x-dsh-session-transfer-confirmation: transfer-session` 确认头与同源校验）
- `POST /plugins/original-version-enhancements/automation/catalog` — 任务目录、投递后清理标记与每个任务的记录条数
- `POST /plugins/original-version-enhancements/automation/history` — 单个任务的运行记录
- `POST /plugins/original-version-enhancements/automation/create` — 新建任务
- `POST /plugins/original-version-enhancements/automation/update` — 修改任务（标题 / 内容 / 规则 / 目标 / 启停）；可带 `expectedUpdatedAt` 做乐观并发（不符返回 409 `schedule_conflict`），规则与原任务相同时不提交规则
- `POST /plugins/original-version-enhancements/automation/run` — 立即投递：先调宿主 `service.run`（有记录）；正在投递时返回 409 `schedule-execution-active`；仍在间隔内时，带 `withinInterval: true` 再调则改用 2 秒后的临时任务（无记录）、投递后自删
- `POST /plugins/original-version-enhancements/automation/auto-clean` — 设置/清除任务的投递后清理
- `POST /plugins/original-version-enhancements/automation/delete` — 批量删除
- `POST /plugins/original-version-enhancements/automation/bind` — 把任务复制到多个会话

后八条需要 Host 的 `schedule` 服务；未挂载该服务的组合里它们不会注册。

## 文案 / Language

界面上的所有文字都在 `locale/lang.json` 里，按 `{ "zh": {…}, "en": {…} }` 组织，键由 `client.js` 引用。
改文案的流程只有两步：

1. 编辑 `locale/lang.json`；
2. 刷新页面。

Host 半侧由 `host/lang.mjs` 通过 `/plugins/original-version-enhancements/lang` 每次请求现读这个文件并带
`cache-control: no-store`，所以不需要重新构建、也不需要重启 DeepSeek Harness。两种语言的键集合必须一致；
删掉一个键会让界面直接显示键名，而 JSON 语法错误会让 Host 返回 500、客户端在控制台说明原因。

## 样式 / Stylesheet

所有样式都在 `css/style.css`（`.tqs-*` 工作步骤切换、`.ove-*` 插件页/归档页/会话卡片/自动化增强面板）。
改样式同样是两步：

1. 编辑 `css/style.css`；
2. 刷新页面。

Host 半侧由 `host/css.mjs` 通过 `/plugins/original-version-enhancements/style` 现读文件、带
`cache-control: no-store` 与 `content-disposition: inline` 应答（路由故意不带 `.css` 后缀：IDM 这类
下载器会按后缀嗅探页面子资源，带后缀时每次刷新都会弹出下载框）；客户端在注册任何插槽之前先取回样式，
所以首屏不会出现无样式闪烁。每个面板各自渲染一个 `<style>`（`data-plugin-css` 标记），这样在只有某一块
界面的页面上也一定带着样式。

⚠️ 本插件自身不再产生任何「会被下载器按后缀抓走」的地址（文案 `/lang`、样式 `/style` 都没有后缀）。
如果刷新界面时仍弹出 IDM 下载框，来源是**别的插件**：它们的 `*.mp3` 等媒体地址会被 IDM 按扩展名拦截。
在 IDM「选项 → 文件类型 / 站点排除」里把 `127.0.0.1` 或 `http://127.0.0.1:*/*` 排除即可，
也可以在 IDM 的「下载列表 → 取消记录」（`%APPDATA%\IDM\UrlHistory.txt` / `cnlurllist2.dat`）里
看到被拦截的真实地址，据此定位是哪个插件。

测试用 Node 内置 runner：`node --test test/*.test.mjs`（或 `npm test`）。
